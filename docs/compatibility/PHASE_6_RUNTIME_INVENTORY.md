Discovery implementation: `d313624`. The default implementation falls back to HTTP for absent/empty provider results. Exact domain/subgroup property keys are captured with runtime security properties and checked for sharing conflicts. The callback keeps only a Weak discovery-state reference. Fetch ignores blank values and retains old addresses on failure; callback rejects only null and preserves Java semicolon splitting. Explicit NameServer configuration skips startup/periodic fetch, not SPI callbacks.

HTTP discovery constructs Java's unit/parameter URL, emits pinned version/content-type/timestamp headers, accepts only 200, decodes UTF-8 with replacement and applies Java trim/CR-before-LF cleanup. Pull dispatch ownership: `f4acff3`. A routing-only MessageRequest trait carries group/mode and opaque owner state; it reuses the existing MessageRequestMode. Concrete PullRequest/PopRequest and process-queue state remain consumer-owned. The FIFO worker selects the current registered consumer at dequeue time, matching Java replacement/missing-group behavior, then invokes optional pull/pop capabilities outside registry/queue locks. Absent capabilities drop the request without claiming actual fetch success. Java's scheduled executor is represented by an independent serial future worker; scheduled request delivery enqueues into FIFO rather than performing consumer fetch itself. Delays, zero/negative delays and equal-deadline insertion order do not spawn per-job tasks. User future/request destruction during queue cleanup happens outside locks.

Explicit scheduling can lazily activate only the scheduled worker while the runtime remains Created; construction alone still starts no tasks and FIFO/transport remain unstarted. Runtime start reuses that worker instead of duplicating it. Failed startup immediately closes/clears queues and joins actual reverse creation order. Normal stop rejects new work, cancels/joins FIFO and grants the scheduled executor Java's 1000ms grace before cancelling/joining pending work. Rust uses typed stopped-state errors rather than retaining requests in an unusable stopped queue. Owning facades must map this internal boundary to their source-defined behavior; no inactive consumer operation is marked COMPATIBLE.
