### Deprecated raw implementation accessor audit (Phase 18)

The pinned Java fixture invokes `DefaultMQPullConsumer.getDefaultMQPullConsumerImpl()` twice and records stable identity, configured group, `CREATE_JUST`, null offset store, null `PullAPIWrapper`, and a constructed `RebalanceImpl`. Rust maps the separate Java impl object to the owning `PullConsumer` and tests pointer identity, configured group, and the pre-start absent offset store. `PullConsumer::pull_api_wrapper` preserves Java's null-before-start result, while `set_pull_api_wrapper` uses a shared `Arc` handle for identity and replacement. Startup creates a fresh unit-aware wrapper and attaches the consumer's shared hook list, matching Java's startup overwrite and live hook-list alias.

The accessor exposes more public methods than the facade delegates. The table records the method-level owner mappings and internal-entrypoint dispositions for that raw surface. `PullConsumer::get_default_mq_pull_consumer_impl` returns a clone of the same `Arc<PullConsumer>` owner; the invoked Java fixture checks stable implementation identity and the Rust accessor test checks pointer identity, so no second mutable implementation object is introduced.

## Phase 18 offset topic-filter correction — 2026-10-20

Java `LocalFileOffsetStore.cloneOffsetTable` and
`RemoteBrokerOffsetStore.cloneOffsetTable` call `UtilAll.isBlank`, which delegates
to Commons Lang `StringUtils.isBlank` / `Character.isWhitespace`. Rust now uses
the same character set in the private shared snapshot path. U+001C–U+001F
select the whole table; U+0085, U+00A0, U+2007 and U+202F are literal topic
filters. Nonblank filters remain exact, without trimming or namespace removal.

`RuntimeOffsetFixtures` directly invokes both Java stores for all 65,536 UTF-16
code units and records the 25 blank units in `fixtures/runtime/offsets.json`
