## P15 verification status

- **P15-V01:** property/reply-header fixtures, invalid helper inputs, invalid timeout-before-send behavior, and malformed reply-host conversion have runnable local checks.
- **P15-V02:** reply/timeout, reply/send-failure and reply/cancellation races have barrier-controlled tests; repeated reply/timeout races assert exactly one terminal remover. The lower-level Rust lease cleanup remains owner-scoped; the public Producer shutdown path now follows the pinned Java group-table and pending-entry behavior. Admission permits are released on drop, reply, send failure, timeout and explicit owner-lease cleanup.
- **P15-U01:** Java fixtures and scripted producer sends cover all six public overloads, outbound correlation metadata, selected queues, successful send without premature callback, no-reply timeout, send failure and callback count.
- **P15-V03:** remains a Phase 19 Docker obligation and is not included in the Phase 15 pass claim.

## Pinned source audit

- The invoked `request-reply.json` fixture inventories the declared public method signatures of Java `RequestCallback` (2), `RequestFutureHolder` (4), and `RequestResponseFuture` (18), and records mutable-future and live-map observations. Rust `RequestResponseFuture` state is the value stored by the shared Core correlation table; `RequestFutureHolder` exposes that table, and inbound completion plus timeout scanning update the same future. Producer callbacks keep the typed `FnOnce(Result<...>)` API through a future callback adapter.
- `client/src/main/java/org/apache/rocketmq/client/producer/DefaultMQProducer.java`: six public request overloads namespace the caller topic and delegate to `DefaultMQProducerImpl`.
- `client/src/main/java/org/apache/rocketmq/client/impl/producer/DefaultMQProducerImpl.java`: request overloads register before async send; one original timeout includes preparation; `requestFail` removes before callback; `prepareSendRequest` writes the three message properties. The async sender uses a 50,000-entry `LinkedBlockingQueue`.
- `client/src/main/java/org/apache/rocketmq/client/producer/RequestFutureHolder.java`: singleton pending map; timeout scan removes before callback; scheduler starts after 3 seconds and repeats every second; `shutdown(producer)` only updates the producer set and shuts down the scanner after the last producer. It leaves pending entries untouched.
- `client/src/main/java/org/apache/rocketmq/client/producer/RequestResponseFuture.java`: successful send alone does not invoke a callback. `executeRequestCallback` uses a private `AtomicBoolean` to run the callback at most once, while reply, timeout or send-failure ownership is separately decided by removing the correlation from the concurrent map. Public timeout, latch, response, send-status and cause accessors are mutable; `requestMsg` is always null in the pinned implementation.
- `common/src/main/java/org/apache/rocketmq/common/utils/CorrelationIdUtil.java`: `UUID.randomUUID().toString()`.
- `client/src/main/java/org/apache/rocketmq/client/utils/MessageUtil.java`: helper validates request and cluster, builds the reply topic and copies reply metadata.
- `client/src/main/java/org/apache/rocketmq/client/impl/ClientRemotingProcessor.java`: receive path decodes `ReplyMessageRequestHeader`, builds `MessageExt`, decompresses best-effort, adds `ARRIVE_TIME`, removes by correlation and returns SUCCESS when no request matches; exceptions return SYSTEM_ERROR with `process reply message fail`.
- `common/src/main/java/org/apache/rocketmq/common/utils/NetworkUtil.java`: reply `bornHost` and `storeHost` conversion splits at the last colon, parses the suffix with `Integer.parseInt`, then constructs `InetSocketAddress`; the invoked reply fixture verifies the corresponding success/error outcomes through `ClientRemotingProcessor`.
