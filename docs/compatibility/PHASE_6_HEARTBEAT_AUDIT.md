## Corrected duplicate consumer metadata mismatch

Actual `MQClientInstance.registerConsumer` accepts two distinct registration keys pointing to the same MQConsumerInner; `prepareHeartbeatData` constructs a fresh ConsumerData for each entry. Consequently equal field values still appear twice in the serialized `consumerDataSet` array. The earlier native `HashSet<ConsumerData>` collapsed these values using structural equality. This was an observable array multiplicity difference, not merely iteration or JVM reference identity.
