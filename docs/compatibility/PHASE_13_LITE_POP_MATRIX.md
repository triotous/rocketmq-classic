## Pinned Java public surface and defaults

The fixture records all `LitePullConsumer` interface signatures and all declared public `DefaultLitePullConsumer` method signatures. It invokes selected public getters/setters and captures config validation. Rust's `new_default` preserves Java's no-argument constructor group (`DEFAULT_CONSUMER`), which is rejected at startup; `set_consume_from_where` now rejects the three enum values Java rejects. Defaults observed from the 5.5.1 artifact include clustering mode, auto-commit enabled, 20 pull threads, a 5-second auto-commit interval, batch 10, all-queue threshold 10000, queue count threshold 1000, queue body-size threshold 100 MiB, max consume span 2000, 5-second default poll timeout, 30-second metadata polling, last-offset consumption and a timestamp 30 minutes in the past. Setting an auto-commit interval below 1000 ms is ignored. The heartbeat builder replaces its retained subscription set with the selector map's built subscriptions. Inherited `ClientConfig` methods are available through `LitePullConsumerConfig::client_config`; their consumer-facing mapping still needs a complete audit.

The Push POP defaults are queue wait-ACK threshold 96, invisibility 60000 ms, and POP batch count 32. The Java `ExtraInfoUtil` fixture records the unmodified receipt string and each decoded routing/offset field. `PopResult` exposes `FOUND`, `NO_NEW_MSG`, `POLLING_FULL`, and `POLLING_NOT_FOUND` plus pop time, invisibility, remaining count and message list.

Typed request/response bodies and low-level POP/ACK RPCs are already present in protocol/core crates. The Rust tree now has a Lite scheduler/polling facade with consume trace dispatch and a Push POP worker/receipt path, with focused state, decoder, receipt-expiry, receipt-lifecycle and scripted assignment tests. This matrix remains `In progress`: P13-V01's remaining method-by-method Lite success/error differential evidence and P13-V03's complete public API/configuration mapping (including RPC-hook construction and inherited `ClientConfig` behavior) are still open. Phase 19 Broker/Docker scenarios remain pending and are not counted here.
