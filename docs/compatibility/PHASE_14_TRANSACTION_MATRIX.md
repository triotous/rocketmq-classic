## Oracle and plan reconciliation

The pinned artifact/source shows two observable differences from the Phase 14 implementation text. `TransactionMQProducer.start()` initializes its executor and starts the base producer without requiring a listener; `sendMessageInTransaction` fails with `TransactionListener is null` if the listener is absent. With a listener configured, the public method wraps the caller message topic in the namespace and the implementation writes `TRAN_MSG=true` and `PGROUP` before the half-send attempt. The pinned fixture records both outcomes. The plan instead asks for callback validation at start and a copied message that does not mutate the caller. The owner baseline reconciliation below chooses the pinned Java outcomes for this implementation.

Owner baseline reconciliation (2026-10-12): the active Phase 14 objective names Java 5.5.1 public behavior and settings as the compatibility baseline. Until superseded, implement these two behaviors from the pinned Java oracle: listener absence does not block start (transaction send fails before message mutation), and a transaction send with a listener mutates the caller message's namespace topic and half-message properties before transport.
