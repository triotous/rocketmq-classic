Rust test names above locate candidate evidence; `consumer.rs:every_consumer_rpc_rejects_unexpected_status_before_decoding`, `extensions.rs:synchronous_extension_status_matrix` and `async_extension_status_and_malformed_matrix` cover additional unknown-code paths. These are **not** a checked-off per-method branch audit. In particular, success with no decoded payload has no meaningful malformed-payload test, whereas a decoded header/body does. `F` fixtures compare code, extension map, body bytes, dispatch semantics and typed result/error classification using local scripted peers; Java's null-pointer malformed-header failures map to Rust's structured `MalformedResponse`, not the same exception type. The Lite future dispatch is labeled ASYNC on the Java side; Rust awaits a request with the same wire mode, not an equivalent callback API. These fixtures do not establish broad method parity. Existing 15 frame fixtures decode standalone responses, not invoked method cases. `P5-U01` and `P5-V01` stay open; `P5-V02` remains Phase 19. `rpc.rs:broker_methods_use_one_attempt_and_honor_deadline` covers all Broker methods; route failover, exhausted deadline, oneway no-pending and expired deadlines are scripted there, but `P5-V03` still needs a complete pending/race audit before closure.
