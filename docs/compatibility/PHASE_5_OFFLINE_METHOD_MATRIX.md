Rust test names above locate candidate evidence; `consumer.rs:every_consumer_rpc_rejects_unexpected_status_before_decoding`, `extensions.rs:synchronous_extension_status_matrix` and `async_extension_status_and_malformed_matrix` cover additional unknown-code paths. These are **not** a checked-off per-method branch audit. In particular, success with no decoded payload has no meaningful malformed-payload test, whereas a decoded header/body does. The eleven `F` fixtures assert exact code, extension map, body bytes, SYNC mode, and typed result/error classification using a local scripted peer; Java's null-pointer malformed-header failures map to Rust's structured `MalformedResponse`, not the same exception type. They do not establish broad method parity. Existing 15 frame fixtures decode standalone responses, not invoked method cases. `P5-U01` and `P5-V01` stay open; `P5-V02` remains Phase 19.
