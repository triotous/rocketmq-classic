## Live raw route table: implemented subset and remaining audit

The retained raw map and its view handles are implemented by `TopicRouteTable`. The actual unstarted runtime oracle captures59 true Java outcomes spanning primitive mutations, null-result remapping defaults, membership/traversal, key/value/entry view operations and cached query/cleanup behavior. Native tests compare all59 observable effects, including Java iterator-removal effects through explicit Rust view removals. Fixture SHA-256 is `f579c47db7ee87efdd315d71d82e918e3cccf7b782505562b459822a29b4e083`.

The Java cases confirm that direct raw writes stay separate from converted publication: replacement changes topic-based address but leaves global publish address unchanged; cached query returns a raw insertion without fetching; clear removes raw lookup while global Broker data stays until offline cleanup; and a later query refetches once into the retained table. Raw put/query accept a null Broker address map although refresh publication rejects it. Conditional operations use route-content equality, including distinct equal copies and ignored Broker metadata fields.

Native writes preserve raw/derived separation and coherent publication. Retained key/value/entry handles mutate the shared raw table; bulk predicates operate on detached snapshots and callbacks do not hold the cache lock. Raw table values now use shared mutable `TopicRouteDataHandle`s so aliases observe setter changes; derived `TopicSnapshot` DTOs remain immutable copies. A detached snapshot taken when traversal starts represents one allowed weakly consistent iterator result: it contains the entries at construction and need not reflect later map changes. Further route audit remains for uninvoked malformed input combinations and the full Phase 6 source/API/settings reconciliation; the route oracle does not close those broader requirements.
