## Live raw route table: remaining implementation contract

The new actual unstarted runtime oracle invokes retained ConcurrentMap put/putIfAbsent/replace/conditional replace/remove/conditional remove/absent/empty key/clear/repopulation and raw getters. Nineteen primitive outcomes are true. Conditional values use TopicRouteData.equals, including distinct equal copies, not owner Arc identity. Broker metadata-only differences are equal by inspected source and invoked conditional removal.

After real refresh, directly inserting replacement raw data changes topic-based address to replacement:10911 but global publish lookup remains master:10911. Cached query returns the inserted value without fetch. Clearing raw map makes raw getter/topic selection absent but leaves global publish metadata; actual offline cleanup then removes it. Subsequent query refetches once and the retained map sees the refresh. Direct raw put/query also accept a null Broker address map even though refresh publication rejects it. This is distinct from unapproved nullable address values, and the existing Option map already represents it.

Required native work must expose live raw access/mutation without pretending it is converted publication. Route fetch/conversion can still atomically publish coherent immutable snapshots, but explicit raw mutations must preserve separate derived Broker/publish/subscribe/endpoint state and raw-dependent lookup/query/change/offline-cleanup behavior. Do not validate/convert map writes as refresh, delete all derived data on clear, reuse owner identity equality or present snapshot as the live table. Rust DTO in-place object mutation and additional ConcurrentMap default operations need further API/input disposition; the bounded oracle is not full collection/GC compatibility. Existing native raw and converted data share TopicSnapshot and cannot currently express these direct-map states. No native table API or its full parity is claimed by the green metadata comparison tests.
