Status: Accepted

## Context

The Java 5.5.1 client decodes `SubscriptionData`, `ProducerData`, `ConsumerData`, and `HeartbeatData` fields with Fastjson 2.0.63. The native DTOs already represented nullable fields and Java constructor defaults, but direct Serde decoding rejected scalar values that Fastjson converts and did not apply Java's primitive coercions consistently.

## Decision

Reuse the narrow `rocketmq-classic-common::serde_fastjson` field decoders for the recorded heartbeat inputs. The covered conversions include Java boolean inputs for `classFilterMode`, `unitMode`, and `withoutSub`; numeric and string inputs for `subVersion` and `heartbeatFingerprint`; scalar-to-string inputs for string fields; and nullable `tagsSet`/`codeSet` elements. Set shape follows the invoked Java coercions: `tagsSet` accepts a singleton string or object (object values become compact JSON strings), while scalar numbers and Booleans reject; `codeSet` accepts singleton numbers, strings, Booleans, and objects (objects become zero). Array elements use the corresponding Java conversions and Set deduplication. `codeSet` decimal tokens retain their exact JSON text so large decimal values narrow to Java's low 32 bits without floating-point rounding. Numeric-to-string conversion retains integer and plain-decimal tokens; exponent tokens use the pinned Java numeric formatting, which converts `1e2` and `1.0e2` to `100.0`. `subVersion` rejects object and array inputs, including an empty object, while the route DTO's separate i32 coercion retains its observed empty-object behavior. The shared parser also normalizes the directly observed Fastjson forms: leading-plus/zero-prefixed numeric values, form feed outside strings, and a BOM at document start. It leaves the tested vertical tab and embedded BOM rejected.

Existing DTO field types, defaults for absent fields, and serialization remain unchanged. Rust returns Serde errors for rejected values; it does not reproduce Fastjson's exception classes or claim full Fastjson grammar equivalence.

## Evidence

`RuntimeHeartbeatFixtures.heartbeatDtoInputCases` had 52 Java inputs at the earlier scalar-coercion checkpoint, covering numeric boundaries, set shapes, nulls, invalid values, nested DTOs, and object/array-to-String coercion. The 21-case string-coercion baseline showed Java preserves object-key order; `serde_fastjson::deserialize_nullable_string` uses a private ordered value (`87dca73`). Set-shape probes show singleton object coercion, scalar rejection for `tagsSet`, Boolean/object conversion for `codeSet`, and HashSet deduplication. Numeric boundary probes cover i32 minimum/maximum, integer overflow rejection, exponent strings, wide decimals, high-precision values around Long limits, and rejection of empty objects/arrays for `subVersion`. The combined high-precision `codeSet` case yields `[-1, 0]`; isolated decimal values `9223372036854775807.0`, `9223372036854775808.0`, and `-9223372036854775809.0` yield `-1`, `0`, and `-1`. Numeric-to-string cases preserve `9223372036854775807.123456789012345678901`; exponent forms produce Java's `100.0`, `100.0`, and `123.45678901234568` for `1e2`, `1.0e2`, and `1.234567890123456789e2`. The differential exposed floating-point loss before the shared decoder fix. Probe/test commits `51191e9`, `cb75740`, `f4272fd`, and `17b46bd`; implementations `e39abf5` and `5e30b73`. The shared grammar probes show Java accepts `+02`, form feed around a token and document prefix, and a leading BOM; it rejects vertical tab and an embedded BOM. `heartbeat_dto_inputs_match_invoked_java_fastjson` checks acceptance and normalized decoded/re-encoded values against the pinned oracle.

`HeartbeatData` now exposes `java_decode`, `java_decode_nullable`, `java_decode_list`, `java_decode_list_nullable`, `java_from_json`, and `java_from_json_nullable` alongside its existing JSON encoder. Direct utility probes (`45404c6`) establish null bytes/strings, JSON `null`, null list input, and a retained null member in `[null,{}]`; tests compare these with the nullable adapters. The heartbeat decoder uses the shared Fastjson input parser from `serde_fastjson`.

The earlier 43-case heartbeat fixture SHA-256 was `bc147764feb4ddfca190c098eb014f585148e7b8989c804922acae5611384612`; the 47-case checkpoint was `387338054f1043053dbeebc14a3dc20893ac450dce19ce5dfebb99657bd7c412`; the earlier 52-case checkpoint was `e183f318134bd5dfa85bcbd80276c3e85c444f3ca0ebbe8231696ef2b4305db7`.

Focused heartbeat and route DTO differentials, full workspace/all-target tests, strict all-target/all-feature Clippy, pinned offline Maven verification (22 scenarios), comparator self-test and manifest validation, formatting, and diff checks pass. This closes these recorded input cases only; other DTO combinations, full Fastjson grammar, and whole-Phase 6 reconciliation remain open.
