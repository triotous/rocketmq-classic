# ADR-0010: Live raw topic routes independent of derived publication

Status: implemented for tested Phase 6 primitives; final acceptance remains open.

## Source contract

Pinned Java MQClientInstance.getTopicRouteTable returns its live ConcurrentMap. Actual oracle19 primitive outcomes include retained-view/getter freshness, equal-copy conditional replacement/removal, empty keys and clear/repopulation. Direct map writes do not fetch, validate, convert, invoke owners or rebuild global Broker/producer/consumer metadata.

Observed actual runtime behavior: replacement changes raw topic-based address but not global publish address; clear removes raw getter/topic selection but Broker data persists until offline cleanup. Cached query returns direct raw data without fetching, including a null Broker address map. Query after clear refetches once and retained table sees publication. Refresh of unchanged invalid raw data returnsfalse before conversion. The reviewed oracle fixes an earlier stale counter baseline after metadata refresh; it did not demonstrate an actual cached-query fetch.

## Native implementation

`dae27fb` exposes ClientRuntime.topic_route_table and cloneable TopicRouteTable. Reads and atomic synchronous put/put_if_absent/replace/replace_if_equal/remove/remove_if_equal/clear operate on the shared raw map. Follow-up `f5431b6` adds `get_or_default` and `put_all`, matching the invoked Java helpers; `put_all` applies independent per-key writes. `a973104` adds `compute_if_absent`, `compute_if_present`, `compute`, `merge` and `replace_all`; callbacks run outside the cache lock. Compute-style remapping callbacks use source route-value semantics and same-key writes wait, while `replace_all` callbacks may be retried when a concurrent write wins before conditional replacement. `06cb233` adds source-equality `contains_value` and `for_each` over a detached snapshot, with callback reentry tested. [ADR-0082](ADR-0082-raw-route-table-remapping-atomicity.md) details both concurrency paths and normal route-refresh serialization. These are raw-only writes and do not convert routes or publish derived topic metadata. snapshot is explicitly detached. Conditional comparisons use source route-content equality (Broker name/addresses only), not owner identity or broad lower DTO Eq.

RouteSnapshot.raw_routes is separate from topics, the last converted publication. Normal refresh publishes raw/converted/Broker state atomically. Explicit raw writes update only raw_routes in a new coherent snapshot; old snapshots keep their map structure and share the route-data handles, so mutations to a retained value are visible through every alias. Derived TopicSnapshot values remain immutable owned copies. Raw getters, topic selection, refresh change detection and offline cleanup consume raw_routes. This represents intentional source raw/derived divergence, not partially completed conversion. Unchanged raw comparison precedes conversion validation; owner-forced publication still validates/rebuilds.

`TopicRouteDataHandle` owns one `Arc<RwLock<TopicRouteData>>`, never runtime/control/transport. Direct `put` retains the exact handle, and `get`, table snapshots, and runtime cached-route queries return aliases to that object. `snapshot()` provides detached inspection; `with_mut()` updates the shared DTO under its write lock. Equality and callback work snapshots values before taking the route-cache write lock. No worker, RPC, setting or dependency is added. Retained tables work after runtime/transport teardown. The pinned Java table oracle confirms the same object is retained on `put` and that setters through either the original or table-returned reference are visible through the other. Other map defaults and malformed raw cleanup/DTO inputs still require source/API reconciliation, not a typed-bound exclusion.

## Nullable live-view collection arguments

Pinned Java `ConcurrentHashMap` calls to `removeAll(null)` and `retainAll(null)` on keySet, values, and entrySet each throw `NullPointerException` before changing the map. `TopicRouteKeySetView`, `TopicRouteValuesView`, and `TopicRouteEntrySetView` now expose `remove_all_nullable` and `retain_all_nullable`; `None` maps to `RuntimeError::InvalidRoute("null topic route collection")`, and the differential verifies the prior mapping remains.
