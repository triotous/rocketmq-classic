# ADR-0009: Live producer and consumer registry tables

Status: implemented for the tested Phase 6 map operations and basic live views; whole-phase acceptance remains open.

## Source and native ownership

Pinned Java client 5.5.1 `MQClientInstance.getProducerTable/getConsumerTable` return actual ConcurrentMaps. Retained views observe replacements and clears; primitive mutations affect selectors without unregister RPCs. `bf4a859` supplies `ClientRuntime::producer_table/consumer_table` and cloneable `ProducerTable/ConsumerTable`, with cloneable key-set, values and entry-set view handles added in `51eb87f`.

Handles share the registry but hold a weak runtime reference. Entries follow existing plan-required weak ownership: callers retain owner Arcs; owner drop leaves a binding, while get returns None and snapshot omits expired owners. len/contains_key count bindings. snapshot is explicitly a detached owned copy. Neither handle retains transport/control resources or an owner/runtime cycle. This is a native ownership boundary, not Java strong-reference/GC equivalence.

## Mutations and lifecycle

Provide get/get_or_default, put/put_all/put_if_absent, replace, containsValue, identity-conditional replace/remove, Java-equality-conditional replace/remove, computeIfAbsent/Present, compute, merge, replaceAll, forEach and clear. The Rust owner traits expose an optional stable `map_value_equality_key`; `replace_if_equal/remove_if_equal/contains_value` compare the expected key with the key captured when the current value entered the table. Owners without a key use Object identity, matching RocketMQ's concrete implementations. Keys are captured before registry locks, so no owner code runs under the registry mutex. The Java 5.5.1 custom-equality oracle covers containsValue and conditional replace/remove for producer and consumer proxies. Remapping closures run outside the mutex and retries use conditional updates; a closure may run again after a concurrent write. `put_all` applies independent per-key writes, as Java `Map.putAll` does.

`keys`, `values`, `snapshot` and `for_each` return/visit detached snapshots. `key_set_view`, `values_view` and `entry_set_view` return retained handles whose contains/length/emptiness/remove/clear calls operate on the current backing map; each view's `snapshot` is detached. Predicate-based `remove_if`/`retain` and collection-based `remove_all`/`retain_all` visit detached snapshots, then apply removals outside the registry lock. Values membership uses the stable Java-equality key captured at insertion. Tests cover direct-put visibility, repopulation, removal, clear and Java `removeIf`/`removeAll`/`retainAll` outcomes. Iterator-removal effects are covered through the equivalent live-view `remove` methods; traversal remains detached and does not claim Java weakly consistent iteration. Exact generic Collection overload signatures are not represented. Dynamically changing owner equality remains under reconciliation.

Every successful put/replacement creates a fresh private lease identity, even for the same owner. Old unregister/rollback leases cannot remove that binding. Map writes neither issue Broker unregister RPCs nor stop owners.

Existing control actors queue writes behind pending unregister transactions; no new actor is created. Closed cancelled replies are skipped before mutation. Before actor creation and after terminal closure, writes operate directly without resource revival. During Starting, addressing callbacks can await a table write on the startup actor itself; direct atomic mutation avoids self-deadlock, and no unregister transaction is active in that state. Reads do not wait for Broker RPCs. Synchronous guards never cross await; owned mutation arguments/returned owners are released outside the registry guard.

Source unregisterProducer/Consumer(group) unconditionally remove the current mapping and invoke best-effort Broker unregister even for absent keys. `3ccaf54` supplies separate public unregister_producer_by_group/unregister_consumer_by_group methods, serialized by the existing control actor. Their bool reports binding removal, not Broker success. Cancelled queued calls do not apply; in-flight cleanup finishes. Terminal retained bindings can be removed without resource revival. Lifecycle/PendingLease cleanup still uses identity leases exclusively; raw map remove still sends no RPCs.
