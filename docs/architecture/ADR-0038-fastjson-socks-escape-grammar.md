# ADR-0038: Match Fastjson SOCKS string escape parsing

Status: Accepted

## EOF comment boundary continuation

Three direct pinned Java 5.5.1 constructor cases establish Fastjson's EOF line-comment boundary: an EOF comment after a complete nested proxy route permits the root object to end implicitly, while EOF inside an unfinished route object or array rejects. The native `recover_fastjson_eof_line_comment` behavior already matches these cases. Oracle/test commit `b468c58`; the SOCKS constructor corpus has 429 cases at `client-config.json` SHA-256 `1f25f9939e05b869005252f52fa9bb65510486e8f3caa74d51559c64ec91409b`. Focused differential and pinned Java fixture generation pass; no production change was required. This closes only this EOF boundary; broader Fastjson/source reconciliation remains open.

## Context

The pinned Java 5.5.1 SOCKS constructor parses `socksProxyConfig` with Fastjson2. Its string escape handling accepts complete `\x` and `\u` escapes even when an ASCII digit is not hexadecimal, converting each invalid digit to zero. It rejects escapes that reach the string terminator before the required number of digits, and it rejects backslash line continuations. For a non-ASCII character immediately after a backslash, Fastjson's `char1` lookup masks the first UTF-16 code unit with `0x7f` before indexing its escape table.

## Decision

Before normalization, match Fastjson's document-boundary scan. Leading NUL, backspace, tab, LF, form feed, CR, space, one BOM, and U+FFFE are skipped; other leading BMP units, including NBSP, reject. Outside strings/comments, Fastjson also skips NUL, backspace, tab, LF, form feed, and CR around tokens. Once the root object has opened, the source-probed units U+0080, U+0088–U+008A, U+008C–U+008D, NBSP, U+00C0, U+00C8–U+00CA, U+00CC–U+00CD, and U+00E0 are accepted at the six tested token boundaries. Other Unicode whitespace and an embedded or trailing BOM reject. A trailing comma is accepted before either nested or root close. The source-probed U+001A sentinel ends parsing at the observed root boundaries; the adapter closes a remaining root delimiter only when no nested value is unfinished. Keep LF that terminates a line comment so following JSON is not swallowed. These rules come from direct Java observations, not a guessed Unicode whitespace table.

Keep the raw SOCKS JSON setting unchanged. During native normalization, rewrite complete `\xNN` and `\uNNNN` sequences to valid JSON Unicode escapes. The escape forms follow different Fastjson 2.0.63 paths: `\x` indexes a bounded lookup table, mapping in-range invalid ASCII digits to zero and rejecting code units above U+0066; `\u` uses a packed UTF-16 decoder that consumes exactly four code units and can produce non-ASCII nibble values. A supplementary scalar can straddle that boundary: its high surrogate completes the fourth digit and its low surrogate remains after the escape. Preserve that low unit when it pairs with a decoded high surrogate; otherwise adapt the unpaired unit to U+FFFD because Rust `String` cannot represent isolated UTF-16 surrogates. For other non-ASCII escape followers, map the first UTF-16 unit through the same low-seven-bit `char1` table.

This is an input-grammar adapter only. It adds no public configuration and does not claim Java exception-class parity.
